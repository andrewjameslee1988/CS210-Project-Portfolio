# CS210-Project-Portfolio
  This is the Repository to store Project 3. The files inside form a program to read a text file of grocery items and makes a count of how many timed each item occurs. It allows users to look up individual item counts, an option to print all items and their frequencies, and to display a histogram of all items with asterisks counting for each occurrence of that item.  This project demonstrates: modular C++ design, input validation, file handling, and data structures for storage.  
  
  I believe that the design i stuck with keeps the code as an easy to maintain, and simplistic modular design that can be adapted and changed to suit different needs over time.  I think that the way i handles the input validation is going to prevent the majority of issues caused by invalid user input.  The normalization i used i would say is also something that makes this work more smoothly, that way it can account for upper-case, lower-case, and multi word items will suit almost anything that is going to be added as an item for the program.  
  I think that i could enhance the code by: adding in more exception handling with try/catch coding to reduce unexpected behavior from the program.  I think that there also could be so tweaks to finding the file, and it's file path that way it can account of differences in file systems.  Lastly it can be made more appealing visually over time, but that can get into a whole different skill set of graphic design for the menu and displays for the program.  
  I think the Normalization was most likely the hardest part to figure out.  It was mostly trying to pick which functions would work better than others so i could use less of them.  Being able to just use a handful of functions to reduce the number of extra steps needed for standardization, helped reduce a bunch of extra coding steps.  It was just a matter of looking at the different functions i could use and picking the ones that applied to the use case more than others. If the program was expanded more, others could even be added in for more in depth standardization.  
  The skills i can use from this project when going into working on others would definitely be: Modular design, debugging, how to handle files, validating users input for programs, and documentation of code functions.  All of these will be skills used in othe C++ projects or even other coding projects in the future.  
  The ways that i made the program maintainable/readable/adaptable are: Breaking down the program for separation of concerns; that way each part had it's own functions and just needed to do those parts well, while at the same time not needing the user to have any access to the parts that were not necessary for them to run the program.  Keeping the naming convention very simplistic makes following the logic and functions of the code nice and easy.   The code comments explain sections or specifics in a way that it lets the the next programmer down the line be able to tell what different sections or lines mean in a straight-forward way.
